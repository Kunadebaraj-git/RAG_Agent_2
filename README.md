# DocMind AI

RAG-powered document Q&A with citations, built with FastAPI, LangGraph, React, and pgvector.

Upload PDFs → ask questions → get answers with page-level citations.

## Stack

| Layer | Technology |
|-------|-----------|
| Frontend | React 18 + TypeScript + Vite + Tailwind CSS v4 |
| Backend | Python 3.11 + FastAPI + SQLAlchemy 2.x + Alembic |
| Database | Neon Postgres + pgvector (HNSW index) |
| Embeddings | HF Inference API (all-MiniLM-L6-v2, 384d) |
| LLM | Groq API (llama-3.1-8b-instant) |
| Agent | LangGraph (TypedDict state, conditional routing) |
| Auth | JWT + bcrypt |
| Deploy | Render (Web Service + Static Site) |

## Environment Setup

Automate setting up `backend/.env` and `frontend/.env` using the setup script:

```bash
python scripts/setup_env.py
```

This script generates `JWT_SECRET` automatically and checks for required credentials.

### Required Environment Variables

| Variable | Description | Where to Get It |
|----------|-------------|-----------------|
| `DATABASE_URL` | Neon Postgres pooled connection string | Neon Dashboard → Project Details → Connection Details → Pooled (`postgresql+psycopg://USER:PASSWORD@HOST-pooler.REGION.aws.neon.tech/rag_db?sslmode=require`) |
| `GROQ_API_KEY` | Groq API key for `llama-3.1-8b-instant` | Groq Console → [API Keys](https://console.groq.com/keys) |
| `HF_API_TOKEN` | Hugging Face Access Token for embeddings | Hugging Face → [Access Tokens](https://huggingface.co/settings/tokens) (Read token) |
| `JWT_SECRET` | Secret key for signing JWT auth tokens | Auto-generated by `python scripts/setup_env.py` using `secrets.token_hex(32)` |
| `FRONTEND_URL` | Allowed CORS origin for backend | Local default `http://localhost:5173` or deployed frontend URL |
| `VITE_API_URL` | Backend API URL used by React frontend | Local default `http://localhost:8000` or deployed backend URL |

## Local Development

### Prerequisites
- Python 3.11+
- Node.js 18+
- A Neon Postgres database with pgvector enabled

### Backend

```bash
python scripts/setup_env.py
cd backend
python -m venv venv
venv\Scripts\activate       # Windows
# source venv/bin/activate  # Linux/Mac

pip install -r requirements.txt

# Run migrations
alembic upgrade head

# Start server
uvicorn app.main:app --reload --port 8000
```

### Frontend

```bash
cd frontend
npm install

# Create .env
echo "VITE_API_URL=http://localhost:8000" > .env

npm run dev
```

### Run Tests

```bash
cd backend
pytest tests/ -v
```

## Render Deployment

1. **Create a Neon database** at neon.tech. Enable pgvector extension:
   ```sql
   CREATE EXTENSION IF NOT EXISTS vector;
   ```

2. **Push to GitHub** and connect Render to the repo.

3. **Create services** from `render.yaml` (Blueprint):
   - Backend: Web Service (Python, free tier)
   - Frontend: Static Site

4. **Set environment variables** in Render dashboard:
   - Backend: `DATABASE_URL`, `SECRET_KEY`, `GROQ_API_KEY`, `HF_API_TOKEN`, `FRONTEND_URL`
   - Frontend: `VITE_API_URL` (your backend URL)

5. Deploy. The start command runs migrations automatically:
   ```
   alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port $PORT
   ```

## Security Notes

### User Isolation
Every database query and vector search is filtered by `user_id`. Document endpoints return 404 (not 403) for other users' resources to avoid information leakage.

### Prompt Injection
The RAG system prompt labels document content as "UNTRUSTED DATA" and explicitly instructs the model to ignore instructions within documents. This is defense-in-depth — no prompt injection defense is 100% effective.

### Upload Validation
Multi-layer: extension → MIME type → file size → PDF validity → page count → text extraction check. No files are saved to disk.

### Authentication
bcrypt password hashing, JWT tokens with configurable expiry, no password/token logging.

## Honest Limitations

1. **Scanned PDFs**: Not supported. pypdf can only extract text streams, not OCR.
2. **Cold starts**: Render free tier sleeps after 15min inactivity. First request takes 10-30s.
3. **Rate limits**: Free tiers on Groq and HF have rate limits. Batch uploads may hit 429s.
4. **RAM**: 512MB on Render free tier. Large PDFs (many pages) may cause OOM during ingestion.
5. **No streaming**: Responses appear all at once, not token-by-token.
6. **Chunking**: Fixed-size chunking doesn't understand semantic boundaries.
7. **LLM reliability**: llama-3.1-8b may not always follow citation instructions perfectly.
